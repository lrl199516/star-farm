# 踩坑与补救记录（LOG）

> 用途：记录每个阶段遇到的问题、原因、解决过程和补救方法，方便复习和避免重复踩坑。
> 规则：每阶段结束、每次踩坑解决后，照下方格式追加一条；问题描述要能复现，报错信息原样复制。

## 记录格式（复制此模板填写）

```
- 日期：YYYY-MM-DD
- 阶段：阶段 X（如：阶段 0 环境与前置）
- 问题描述：一句话说清发生了什么
- 报错信息：原样粘贴报错文本
- 原因分析：为什么会出现
- 解决过程：试过哪些方法，最后怎么解决的
- 补救措施：当时如何恢复（Git 回退 / 存档恢复 / 日志回溯等）
- 学到什么：下次如何避免，或如何快速定位
```

## 记录

### 示例：Git 首次提交报错（阶段 0）

- 日期：2026-08-08
- 阶段：阶段 0 环境与前置
- 问题描述：执行首次提交时提示缺少用户信息，提交失败。
- 报错信息：`*** Please tell me who you are.`（大意：Git 不知道"你是谁"）
- 原因分析：Git 提交必须记录作者信息，新电脑没有配置用户名和邮箱。
- 解决过程：用 `git config` 在项目内设置用户名和邮箱后，重新提交成功。
- 补救措施：配置类问题无需回退；设置完成后重试即可。
- 学到什么：新环境装完 Git 第一件事是配置用户名和邮箱；Git 的报错信息里通常会直接提示解决方法。
