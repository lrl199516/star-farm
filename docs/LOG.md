# 踩坑与补救记录（LOG）

> 用途：记录每个阶段遇到的问题、原因、解决过程和补救方法，方便复习和避免重复踩坑。
> 规则：每阶段结束、每次踩坑解决后，照下方格式追加一条；问题描述要能复现，报错信息原样复制。

## 记录格式（复制此模板填写）

```
- 日期：YYYY-MM-DD
- 阶段：阶段 X（如：阶段 0 环境与前置）
- 问题描述：一句话说清发生了什么
- 报错信息：原样粘贴报错文本
- 原因分析：为什么会出现
- 解决过程：试过哪些方法，最后怎么解决的
- 补救措施：当时如何恢复（Git 回退 / 存档恢复 / 日志回溯等）
- 学到什么：下次如何避免，或如何快速定位
```

## 记录

### 示例：Git 首次提交报错（阶段 0）

- 日期：2026-08-08
- 阶段：阶段 0 环境与前置
- 问题描述：执行首次提交时提示缺少用户信息，提交失败。
- 报错信息：`*** Please tell me who you are.`（大意：Git 不知道"你是谁"）
- 原因分析：Git 提交必须记录作者信息，新电脑没有配置用户名和邮箱。
- 解决过程：用 `git config` 在项目内设置用户名和邮箱后，重新提交成功。
- 补救措施：配置类问题无需回退；设置完成后重试即可。
- 学到什么：新环境装完 Git 第一件事是配置用户名和邮箱；Git 的报错信息里通常会直接提示解决方法。

### 脚手架生成了错误的项目模板（阶段 0）

- 日期：2026-08-08
- 阶段：阶段 0 环境与前置
- 问题描述：用脚手架创建前端项目时，期望生成"Vue 3 + JavaScript"模板，实际生成的是 TypeScript 空白模板。
- 报错信息：命令行提示 `Unknown cli config "--template"`（大意：参数没被正确识别）。
- 原因分析：`npm create` 把 `--template` 当成了 npm 自己的参数，没有传给脚手架，模板参数丢失，脚手架回退到了默认模板。
- 解决过程：先删除错误的 `client/` 目录（已确认路径在工作区内），改用 `npx create-vite` 直接传参的方式重新生成，检查 `package.json` 和 `src` 目录确认模板正确，再安装依赖并验证构建和本地运行。
- 补救措施：删除错误目录并重新生成；生成后第一时间检查关键文件（package.json 里有没有 vue、src 里有没有 main.js/App.vue）确认没选错。
- 学到什么：脚手架参数传不对会"静默生成错误模板"，所以生成后必须做"结果检查"，而不是直接开写代码。
