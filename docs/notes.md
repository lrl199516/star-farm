# 《星际农场》项目要点速查

> 本文档是这个项目的"记忆卡片"，集中记录所有已锁定的设计决策与学习要点。
> 约定：计划一旦调整，本文档必须同步更新，保持"文档与计划一致"。

## 1. 项目一句话介绍

一款**太空种田 + 星宠养成**网页游戏，玩法体系参考 QQ 农场（核心单机机制），故事背景设定在太空星球"希望星"。玩家通过网页链接进入，**各玩各的、互不干扰**，进度保存在服务器上，换设备不丢。

## 2. 技术栈速查

| 工具 | 作用 | 一句话类比 |
|---|---|---|
| 浏览器（Chrome） | 玩家玩游戏的窗口 + 开发者的调试台（F12） | 观众席 + 监控室 |
| VS Code | 代码编辑器 | 高级记事本 |
| Git | 版本控制：记录每次改动、随时回退 | 时光机 |
| GitHub | 远程仓库：备份 + 作品展示 | 备份柜 + 展示台 |
| Node.js 24 | 让 JavaScript 在电脑/服务器上运行 | 给 JS 装发动机 |
| Vue 3 + Vite | 前端框架 + 开发服务器/打包工具 | 界面与数据的对讲机 + 搅拌机传送带 |
| Express | 后端框架：接收请求并回应 | 餐厅前台 |
| SQLite（node:sqlite） | 数据库：用单个文件存所有玩家存档 | 档案柜 |

要点：前端和后端都用 JavaScript，学一次两边通用。

## 3. 目录结构速查

```
star-farm/（仓库根目录）
├── README.md       项目说明
├── docs/           文档（要点速查、踩坑记录、验收清单）
├── client/         前端代码（Vue 3 + Vite）
├── server/         后端代码（Node + Express）
├── scripts/        辅助脚本（启动、备份存档等）
├── deploy/         部署配置（PM2 等）
└── .gitignore      不入库清单
```

前端内部（client/src/）：

- components/ 可复用组件（田地格子、宠物卡片、商店抽屉等）
- stores/ 游戏状态（game.js，单一数据源）
- services/ 网络与存档服务（api.js、storage.js）
- data/ 游戏数值配置（crops.js、pets.js、config.js）
- assets/images/crops、assets/images/pets、assets/images/ui、assets/audio 素材按类别归档
- styles/ 全局样式

命名规范：

- 目录和文件：英文小写 + 连字符（如 crop-card.vue）
- Vue 组件：大写驼峰（如 CropCard.vue）
- 提交信息："改动类型 + 简述"（如 feat: 添加种植功能）

## 4. 游戏机制要点

**核心闭环：种植 → 收获 → 喂星宠或卖钱 → 星宠成长 → 繁育 → 卖后代换金币 → 买更多种子和宠物 → 农场升级解锁新土地。**

**种田：**

- 12 格地随农场等级逐批解锁，初始 4 格
- 每块田 4 个生长阶段：播种 → 发芽 → 生长 → 成熟
- 成熟后 2 小时宽限期（可配置），超时枯萎，枯萎可铲除重种
- 收获作物 +5 经验

**农场等级：** 每级所需经验 = 等级 × 20；等级同时解锁新作物和新宠物。

**作物（太空命名）：**

| 作物 | 解锁 | 种子价 | 生长时间 | 售价 | 喂食恢复 |
|---|---|---|---|---|---|
| 星光萝卜 | 初始 | 2 | 5 分钟 | 5 | +10 |
| 火星番茄 | Lv2 | 5 | 30 分钟 | 12 | +20 |
| 太空莓 | Lv4 | 10 | 2 小时 | 28 | +30 |

**星宠：**

| 星宠 | 解锁 | 蛋价 | 最爱作物（恢复双倍） |
|---|---|---|---|
| 星猫 | 初始 | 50 | 火星番茄 |
| 星际犬 | Lv3 | 100 | 太空莓 |
| 月兔 | Lv5 | 150 | 星光萝卜 |

- 宠物栏上限 10 只，蛋也占一格
- 四阶段：**蛋 → 幼崽 → 成年 → 完全体**，宠物永不消失
- 蛋：孵化倒计时（默认 10 分钟）→ 孵出幼崽，性别随机（公/母）
- 幼崽 → 成年需 100 经验；成年 → 完全体需 200 经验
- 喂食消耗作物库存，同时获得等值经验；玩耍 +10 经验，5 分钟冷却
- 饱食度/心情每游戏小时 -4 / -2，只影响繁育，不致死

**繁育条件（全部满足才可，100% 产蛋，无随机失败）：**

- 同一种类 + 一公一母
- 双方都是成年及以上
- 双方饱食度、心情 ≥ 60
- 双方冷却结束（默认 12 小时）

**出售规则：**

- 蛋不可卖；幼崽/成年/完全体可卖
- 售价 = 种类底价 × 阶段倍数 + 等级加成（幼崽 ×1、成年 ×2、完全体 ×4、每级 +5）
- 出售前必须弹确认框

**重要：** 所有成长/衰减/孵化/冷却/枯萎都基于**时间戳计算**（不是定时器），所以离线时游戏也会正常推进。这是排查"时间相关 bug"时的第一检查点。

## 5. 界面设计要点

- 单屏主界面：田地 + 宠物**同屏常驻**，不需要切换页面
- 宽屏：田地左、宠物右并排；窄屏（手机）：田地上、宠物下，宠物区可折叠
- 商店做成抽屉/弹窗，买卖完关闭回到原地
- 点击田地格子 / 宠物，就地弹出操作卡（种植、收获、铲除、喂食、玩耍、繁育、出售）
- 顶部信息栏常驻：昵称、玩家 ID、金币、农场等级、经验条
- 设置（玩家 ID、昵称、存档导出/导入）从齿轮按钮打开弹窗
- 开局显示太空背景文案 + 新手引导

## 6. 数据与后端要点

**存档结构（单一数据源；本地 key：starfarm_save_v1；服务器存 JSON）：**

```js
{
  version: 1,
  coins: 0,
  farm: { level, xp, plots: [...] },
  inventory: { seeds: {...}, crops: {...} },
  pets: [
    { id, typeId, name, gender, stage, xp, hunger, mood,
      hatchUntil, breedCooldownUntil, bornAt }
  ],
  updatedAt: 时间戳
}
```

**后端 API（Node 24 + Express + 内置 node:sqlite）：**

- POST /api/players —— 创建玩家，返回匿名 ID
- GET /api/players/:id —— 查询玩家信息
- GET /api/players/:id/save —— 下载存档
- PUT /api/players/:id/save —— 上传存档（服务端校验 updatedAt，旧的拒绝、新的覆盖）
- GET /api/health —— 健康检查

**同步策略：**

- 启动：先渲染本地缓存 → 再从服务器拉取 → 以 updatedAt 较新者为准合并
- 每次修改后防抖 3 秒上传
- 断网：本地照常玩，联网自动重试
- 换设备：在新浏览器输入"玩家 ID"即可找回存档

**开发/生产约定：** 开发时前端 5173 端口、后端 3000 端口，Vite 把 /api 代理给后端；生产时前端构建后由 Express 托管静态文件。

## 7. AI 协作六条协议

1. **小步任务**：一次只让 AI 改一件事，写明"当前行为 + 目标行为 + 约束"
2. **要说明**：让 AI 说清改了哪些文件、为什么改、有什么风险
3. **先读后跑**：收到代码先通读，不懂就问"这行是干嘛的"，再运行
4. **先自查再问**：出错先自己复现定位，再带上下文问 AI，不让 AI 盲猜
5. **先提交再改**：AI 动手前先 Git 提交，出错用 Git 回退
6. **复盘记录**：每阶段把踩坑和补救写进 docs/LOG.md

## 8. 排查错误四步法

**复现 → 看报错 → 二分定位 → 带上下文问 AI**

常见排查位置：

- 前端问题：浏览器调试台（F12）的 Console（报错）、Network（请求）、Sources（断点）
- 后端问题：服务器日志（PM2 logs / Express 输出）
- 代码改动问题：git diff 对比改动前后，git log 看历史
- 时间相关 bug：先检查存档里的时间戳是否正确

## 9. 补救措施清单

| 情况 | 补救办法 |
|---|---|
| 代码改坏了 | git restore（未提交）/ git revert（已提交） |
| 本地文件全没了 | 从 GitHub 克隆回来（git clone） |
| 游戏进度丢了 | 存档导出/导入；本地损坏自动备份并从服务器恢复 |
| 服务器存档坏了 | 服务端保留备份，可恢复 |
| 线上出问题 | 看服务器日志回溯原因 |

## 10. GitHub 使用规范

- 提交信息格式：feat:（新功能）/ fix:（修 bug）/ docs:（文档）/ refactor:（重构）/ chore:（杂项）
- 习惯：每个小任务完成就提交 + 推送，GitHub 同时是远程备份
- 仓库默认公开（方便展示），可随时改私有
- .gitignore 必忽略：node_modules/、client/dist/、server/data/*.db、.env、日志文件
- 服务器密钥等敏感信息只放服务器环境变量，绝不进仓库

## 13. 常用命令速查

| 想做什么 | 在哪个目录 | 命令 |
|---|---|---|
| 安装依赖 | client/ 和 server/ | npm install |
| 启动前端（开发） | client/ | npm run dev |
| 启动后端（开发） | server/ | npm run dev |
| 构建前端（上线前） | client/ | npm run build |
| 查看改动状态 | 仓库根目录 | git status |
| 提交改动 | 仓库根目录 | git add . 然后 git commit -m "feat: 说明" |
| 推送到 GitHub | 仓库根目录 | git push |
| 回退未提交的改动 | 仓库根目录 | git restore <文件名> |
| 回退已提交的改动 | 仓库根目录 | git revert <commit> |
| 从 GitHub 拉回代码 | 任意目录 | git clone <仓库地址> |
| 看服务器日志 | 服务器上 | pm2 logs |

> 提示：git reset --hard 会丢掉改动，新手阶段尽量用 git restore / git revert。
